Shepherd

A Kubernetes-style reconciliation control loop for container orchestration. This playground is a teaching-accurate JavaScript reimplementation of the Shepherd engine: deploy apps, watch the scheduler bin-pack pods onto nodes, scale, and kill nodes to see the reconciler restore desired state.

github.com/pavanchow/shepherd ↗

How to use this playground

Shepherd never overcommits a node. It filters feasible nodes, bin-packs onto the tightest fit, and loops until observed state equals desired state.

  • Deploy an appName it, pick a replica count and per-pod CPU/mem requests. Optional anti-affinity spreads at most one replica per node.
  • Scale − / +Change desired replicas on any app; the reconciler creates or removes pods and reschedules to converge.
  • Kill nodeFails a node, marks its pods Lost and frees its capacity. The reconciler reschedules replacements onto healthy nodes.
  • Add nodeAdds fresh capacity to the cluster so stuck (Pending) pods can finally fit.
  • Step reconcilerRuns exactly one reconcile pass so you can watch convergence tick by tick.
  • Auto-runTicks the reconciler continuously until every app reaches its desired Running count.

Guided tour (follow in order)

  1. See bin-packing: Deploy web with 4 replicas, cpu 300m, mem 256. Notice pods pack tightly onto the fewest nodes rather than spreading evenly.
  2. See scaling: Press + on web a few times and watch new pods get created and bound until the app shows a green converged badge.
  3. See failure recovery: Click Kill node on a node that hosts web pods. They go Lost, observed drops below desired, and the reconciler reschedules replacements onto the surviving nodes.
  4. See insufficient capacity: Scale an app higher than the cluster can hold. It settles on an orange insufficient capacity status. Then press Add node and watch the Pending pods finally bind.
  5. See anti-affinity: Deploy an app with anti-affinity on and 3 replicas; each replica lands on a different node (one-per-node spread).
